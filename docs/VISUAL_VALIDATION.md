# Sprint 3 visual readability

Local Windows/Edge acceptance uses synthetic routes only. Run `node scripts/acceptance/visual.mjs` from the repository root after installing dependencies. The opt-in script owns a localhost dev server and an isolated headless Edge session. It writes 384 PNG frames and geometry reports under ignored `artifacts/sprint3/visual/` and `visual.json`. No screenshot, benchmark route or diagnostic is sent by the product.

Matrix: eight deterministic geometries (dense, four disconnected segments, antimeridian, long-distance, 86–89° latitude, metre-scale, coastal, extreme antipodal oscillation), Atlas/Night, Compatibility/Standard and 16:9/9:16: 64 configurations. Ordinary cases have 100 points; the deliberately implausible extreme-distance case has the full allowed 50,000 points. The source is synthetic; its elevation and distance are not a real journey. Titles use 200 UTF-16 units, with ellipsis only in presentation. A browser regression also exercises a 200-unit emoji title without splitting code points.

Six timestamps per configuration: intro 1s, early replay 3s, mid-replay 10s, a timestamp one frame after the actual distance-derived first segment boundary (or 10.02s for a single segment), end of replay 17.99s, outro 19s. All 384 captured frames passed measured glyph bounds and start/finish-label intersection checks. These checks complement visual inspection; they do not prove usability on a physical phone. Ordinary preview tests retain keyboard/mobile viewport interaction. Shared preview/export frame state and exact Canvas pixels are tested at the same timestamp; lossy H.264 decoding is independently verified separately.

## Observed defects and targeted changes

- The previous 0.01° minimum view span made a ~1.4m route nearly a point; its endpoint labels overlapped. Nonstationary geometry now has a bounded 0.0001° minimum span; stationary geometry retains the previous 0.01° view. Coordinates/distances are unchanged. Metre-scale endpoints become distinguishable while extreme zoom stays bounded. Very tiny tracks can still have close markers; their labels are separated outside the shared footprint.
- Endpoint labels use a small opaque map-colour backing and safe map-area margins. Close endpoints place labels away from both markers; coincident endpoints retain one `Старт / финиш` label. No route bridges or fabricated map detail.
- Tracks below 1km use metres with up to one decimal, consistently through all scenes and the UI. Longer tracks retain two-decimal kilometres. Replay time is still video time; no actual speed/trip duration is invented. Very large recorded-distance counters fit the available width by reducing their font, without shortening or changing the value. Maximum-series elevation/point-count text fits too.
- Title ellipsis and static metric text/font sizing are prepared once per renderer. The validated chosen title stays unchanged and is redrawn safely with Canvas text. This removes repeated long-title text measurement during every frame. Performance comparison is in PERFORMANCE.md.
- Untravelled Atlas line changed from #7c9982 to #667f6d, increasing contrast against land from 2.34 to 3.27. Travelled Atlas line is #216542, with 5.25 against land and 1.60 against the untravelled line; its greater width and moving marker provide additional distinction. Night track #769382 has 3.73 against land (previous #638171: 2.93). Both route colours exceed 3:1 against both flat land/water surfaces; ink/secondary overlay text exceed 4.5:1 on their backing. Unit tests use the standard sRGB relative-luminance calculation. These thresholds follow [W3C non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html) and [text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html); this is not a claim of a complete accessibility audit. Antialiasing/thin outlines and arbitrary overlapping geometry can affect local visual perception.

Representative inspected evidence includes short Atlas portrait/mid-replay, coastal Night Standard landscape/mid-replay, extreme Atlas portrait/outro, antimeridian Standard landscape, polar Night Standard portrait/outro and long Atlas Compatibility portrait. Intro/outro, both styles/aspects and segment-transition frames remain available for review. Critical endpoint geometry stays inside the map area; title, counter and supplementary fact stay inside the frame. A 5,000-point browser test additionally verifies direct/incremental/backward-seek pixel identity and unchanged pixels in every disconnected segment gap.

## Geography and remaining limits

Retain the route-centred equirectangular projection with latitude-scaled longitudes, static fit and north-up orientation. There is no demonstrated need for a replacement projection in this sprint. Geographic distance continues to use Haversine on original GPX edges; projection never changes it. High-latitude outlines/angles are approximate: a single cosine at the middle latitude cannot represent every latitude's longitudinal scale. On the 86–89° test, cos(87.5°)/cos(86°) ≈ 0.625 and cos(87.5°)/cos(89°) ≈ 2.50. The route is framed and finite, but the picture is not a distance/angle-preserving navigation map. At the poles the cosine floor keeps calculations finite.

Natural Earth 1:110m is deliberately coarse. Coastlines may look angular; small islands/streets can be absent. For tiny local routes the view may contain only a flat land/water area and grid. That is the honest fallback: only the supplied GPX geometry is shown in detail. No street, road, city/country label, geographic feature or online tile is guessed. The UI/README explain the map's limits. Physical mobile readability, Safari rendering on Apple hardware and GPU VRAM remain unverified; screenshots/emulation do not settle those questions.

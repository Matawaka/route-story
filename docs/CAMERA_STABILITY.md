# Спокойное сопровождение длинных маршрутов и минутный экспорт

Запрос владельца 2026-10-13 продолжает PR26; публичная версия пока не изменена. Исходный checkpoint для сравнения: `9eca4e2777d6d4d1a8e5c09375c9aaf2ecac140f`.

Причина: камера усредняла собственное положение, но смотрела на мгновенное положение маркера. В извилистом треке это меняло горизонтальное направление взгляда на десятки градусов за кадр; почти вертикальный взгляд усиливал эффект. Маркер отражался по одному короткому ребру, включая локальные зигзаги.

Для 3D-маршрутов длиннее 5 км план усредняет точку обзора только внутри сегмента, сопровождает её с фиксированным северным направлением и использует верхнюю высотную огибающую сегмента. Прямолинейная интерполяция сохраняет доказательство полного коридора. Непрерывность GPX не выдумывается: между независимыми сегментами остаётся дискретный переход. Короткие Furka/референсные пролёты сохраняют прежний план.

Сглаживается камера, а не маршрут: маркер и цветная линия используют исходную временную шкалу, реальные координаты и расстояния. LOS проверяется как к точке обзора, так и к настоящему маркеру. Минимальный клиренс 350 м, потолок 80 км, no-data и ограничение масштаба фотографии сохранены. На длинной обзорной сцене высота может увеличиться: это раскрываемый компромисс стабильности и качества исходного слоя.

Направление маркера вычисляется по хорде окна 100–250 м внутри текущего сегмента. Окно ограничено, поиск двоичный, без полного обхода GPX на кадр. При почти вертикальном движении (горизонтальная компонента менее 15%) иллюстрация остаётся нейтральной. Она остаётся вертикальной; направление показывается отдельной стрелкой. История проигрывания не используется.

Вариант 60 секунд: 2 секунды вступления, 56 повтора, 2 финала при стандартной конфигурации; 1440 кадров, 24 FPS, прежние 360p/1.5Mbps и 720p/5Mbps. Только минутный файл имеет предел 48 МиБ (+1 МиБ контейнер); старый предел 32 МиБ не изменён. Все остальные длительности, включая произвольные 61 секунду, отвергаются. Рендерится один кадр за раз, без накопления массива кадров.

Воспроизведение проверки (PowerShell, локально, после явного согласия на области владельца):

```powershell
$env:BUILD_AUTO_GEOGRAPHY='1'
$env:SWISS_BASELINE='0'
npm.cmd run dev -- --port 4195 --strictPort
# В другом терминале: собственный GPX остаётся вне Git.
node scripts/acceptance/automatic-geography.mjs 'C:\path\track.gpx' track-smooth --full --minute
```

Опция `--study` сама извлекает исторический модуль камеры из checkpoint Git в игнорируемый `.reference/smoothing/terrain-camera.ts` с импортами `../../src/...`. Она сравнивает один DEM, маршрут, timestamp и размер вывода, меняя только план камеры; сохраняет кадры и максимальный/p95 поворот на кадр. Материалы пользовательских маршрутов сохраняются только в игнорируемых локальных artifacts. Историческая приёмка автоматической географии остаётся в AUTOMATIC_GEOGRAPHY_EVIDENCE.json; новая приёмка записывается отдельно.

## Строгая воспроизводимость кадров

Повторные проверки выявили редкое расхождение одного канала одного фонового пикселя на один уровень, а прямое смешивание GPU/CPU Canvas давало другой вариант округления значка. Допуск не увеличен. Теперь WebGL framebuffer dithering явно выключен, фон читается как RGBA, подписи/значок компонуются в одном фиксированном CPU Canvas, и целиком собранные байты копируются в любой Canvas назначения. Все проверки точного кадра/seek/экспорта и прежние проверки закрытия рельефом сохраняются. Перехватчики тестов для подписи/матрицы значка перенесены на настоящий Canvas композиции; итоговые кадры по-прежнему проверяются на конечном Canvas и независимым декодером.

Буферы ограничены текущим кадром: два массива RGBA плюс CPU Canvas, примерно 10,55 МиБ при 1280×720; временная финальная копия ещё примерно 3,52 МиБ. Это оценка только новых пиксельных ресурсов, не общий RAM/VRAM браузера. Они освобождаются при dispose/ошибке/pagehide. Последовательность видеокадров не сохраняется в памяти. Цена — более медленный экспорт, раскрытая в сравнении измерений ниже; гарантию общей мобильной памяти не заявляем.

Финальная локальная проверка Windows10.0.26200 / Edge155.0.4283.45: Mont Blanc и Malerweg, каждый с реальными 20s1280×720,30s720×1280 и60s в обоих аспектах. Каждый 60s MP4:1440 кадров/H.264/24FPS/точные PTS, полное FFmpeg-декодирование и не-пустые меняющиеся кадры. Preview/исходный кадр кодировщика/обратный seek совпали без пиксельного допуска. Два дополнительных повтора после отмены также независимо декодированы. На одном Mont Blanc запуске был реальный сетевой timeout, одна явная кнопка Retry восстановила подготовку; ошибка сохранена в отчёте. Приложение не получает бесконечных автоматических повторов.

При сравнении на одном DEM/маршруте/размере во время обычного replay: максимум смены bearing на кадр Mont Blanc20s28,17°→0°, Malerweg20s24,81°→0°. Это измерение поворота, а не доказательство зрительского комфорта/удержания. Панорамное перемещение продолжается. Native-память измерена OS Get-Process по уникальным childPID из изолированного CDP-сеанса; GPU VRAM и JS heap отдельно NOT MEASURED. Сводные фактические видео-хэши, одиночные времена экспорта и память находятся в CAMERA_STABILITY_EVIDENCE.json.

Физическая мобильная приёмка минутного режима пока NOT TESTED. Прежние проверки других версий не доказывают поддержку 60s на телефоне. Публикация требует отдельного одобрения владельца и защищённого Pages workflow.

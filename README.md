# Route Story

**MVP 1.7 — интерактивный монтаж.** Локальное приложение превращает GPX в видео: маршрут → стиль → replay → редактор → H.264 MP4. Русский интерфейс, Vite/TypeScript, Canvas 2D и один существующий WebGL2-контекст для 3D. GPX не отправляется на сервер и не сохраняется в браузерном хранилище.

[Публичный сайт](https://matawaka.github.io/route-story/) · [версия и SHA последней публикации](https://matawaka.github.io/route-story/release.json). **1.7.0 реализована и слита** через [PR #31](https://github.com/Matawaka/route-story/pull/31) и [PR #32](https://github.com/Matawaka/route-story/pull/32). Проверенный main — `9efbc360b50e293d09cc8d2ce7fb34b89a171950`; [его CI прошёл](https://github.com/Matawaka/route-story/actions/runs/38849322196). Публичный сайт обновляется отдельно через защищённый ручной Pages workflow; его фактический `version`/`sourceCommit` указаны в `release.json`. [Итог приёмки и медиа](docs/MVP17_EVIDENCE.json).

В доступной 3D-сцене нажмите **«Настроить историю»**. Карточки показывают настоящие кадры; можно выбрать проверенный ракурс для каждого формата, изменить время эпизода, подробнее показать участок, просмотреть одну сцену, отменить или повторить правку. Весь исходный маршрут и разрывы сохраняются. Время анимации является художественным, а не записанной скоростью поездки.

**«Сохранить проект»** создаёт `.rstory.json` без GPX, координат и картинок. Для повторного открытия нужен тот же исходный GPX с совпадающим SHA-256; собственную картинку маркера следует выбрать отдельно. Решения камеры повторно проверяются, проект не может подставить готовый сертификат безопасности.

Экспорт: 10/20/30/60 секунд, 24 FPS, 16:9/9:16, 360p/720p/1080p и экспериментальный 4K при работающем H.264. 4K на 60 секунд требует прямой записи в файл. Выходное разрешение не увеличивает исходную детализацию фотографий. Физические macOS/iOS/Android, нативный диалог сохранения и весь набор длинных отредактированных Full HD/4K остаются непроверенными.

Подготовленные локальные фото/DEM доступны для Согне и Фурки. Экспериментальный автоматический поиск Sentinel/Copernicus требует согласия на передачу округлённой области, сохраняет GPX локально и не обещает мирового детального покрытия. Источники и подписи сохраняются в видео. Лимиты пакетов, ресурсов и непрерывные проверки камеры не изменены.

[Работа с редактором и приёмка 1.7](docs/MVP17.md) · [проверенные конкурсные медиа](docs/COMPETITION_CHECKPOINT_2026-10-15.md) · [ограничения Full HD/4K](docs/HIGH_RESOLUTION_EXPORT.md) · [источники и лицензии](THIRD_PARTY_NOTICES.md).

## Локальный запуск

Для подготовки кандидата MVP 1.7 из чистого checkout:

```powershell
git clone https://github.com/Matawaka/route-story.git
cd route-story
git switch codex/competition-evidence-20261015
npm.cmd ci
npm.cmd run build
npm.cmd run preview
```

В Windows PowerShell используйте `npm.cmd` и `npx.cmd`: это запускает командные обёртки Node.js и не требует разрешать выполнение `npm.ps1` или менять ExecutionPolicy. В Linux/macOS используйте `npm` и `npx` без `.cmd`.

```sh
git clone https://github.com/Matawaka/route-story.git
cd route-story
git switch codex/competition-evidence-20261015
npm ci
npm run build
npm run preview
```

Для публичного MVP 1.6 выберите `git switch main`; для архивного выпуска — `git switch --detach v1.0.0`. Для полного кандидата с локальной Фуркой и Согне перед сборкой задайте `BUILD_SWISS_PACK=1` и `BUILD_IMAGERY_PACK=1` (в PowerShell: `$env:BUILD_SWISS_PACK='1'`, `$env:BUILD_IMAGERY_PACK='1'`). Автоматическая география включается отдельно через `BUILD_AUTO_GEOGRAPHY=1` и требует согласия в интерфейсе. Команды Linux/macOS приведены для воспроизводимости сборки. Для запуска нужен браузер с Canvas 2D, File/Blob и XML DOM; для экспорта дополнительно WebCodecs H.264. Общий минимальный объём RAM для всех устройств не установлен.

Откройте адрес localhost, напечатанный Vite (обычно http://127.0.0.1:4173). Для разработки в PowerShell: `npm.cmd run dev`. Требуется Node.js 22.12+; проверено на Node 24.19.0. Экспорт требует HTTPS или localhost и WebCodecs H.264; поддержка проверяется на выбранных размерах. Новый кандидат проверен на Windows10.0.26200/Edge155.0.4283.45, включая 20/30s720p с моноколесом. Прежние автоматизированные браузерные результаты сохранены в [COMPATIBILITY](docs/COMPATIBILITY.md) и [SUPPORTED_PLATFORMS](docs/SUPPORTED_PLATFORMS.md); Playwright WebKit на Windows поддерживает предпросмотр, но не MP4. Владелец ранее сообщил об успешных проверках принятого DEM-режима на Xiaomi14/Pad2/MacBookM2 в Chrome/Brave/Safari, без версий и точных пар устройств/браузеров. Это не новая приёмка фото-динамики/маркеров на физических устройствах и не доказательство универсальной мобильной поддержки. Новый native/GPU-memory замер отсутствует.

## Маршруты, приватность и ограничения

Загрузите свой GPX или выберите синтетическое «Норвегия · Sogne · 3D-демо», выберите «Цвет пути → Уклон · 3D», «Темп → По уклону» и «Маркер → Моноколесо». Подъём красный/оранжевый, спуск зелёный; стрелки/проценты в легенде помогают различать категории. Темп является стилизацией видео, а не измеренной скоростью. Полные высоты GPX имеют приоритет; иначе используется покрывающий DEM, без смешения источников. Ненадёжные/отсутствующие высоты дают явно нейтральный результат. В 2D работает маркер и темп, путь сохраняет одноцветное оформление.

Встроенный «Шах - вкрутанидзе» использует утверждённый владельцем цветной PNG: шлем, оранжевый рюкзак и зелёный туристический багаж. В 3D читаемая аннотация привязана к точному положению на DEM; скрытое горой положение обозначается пунктиром и подписью «За рельефом». Доступны три размера и прежний режим скрытия за рельефом. Подписи старта/финиша избегают картинки.

Для своего маркера выберите локальный статический PNG/WebP/JPG до 2 MiB, 2048×2048 и 4 млн пикселей. В памяти остаётся один уменьшенный растр 256×256; JPEG EXIF-поворот учитывается. JPG сохраняет исходный фон: автоматического удаления чёрного цвета нет. SVG/анимация/внешние ссылки отклоняются. Изображение не загружается на сервер, не сохраняется и не меняет активный экспорт. [Источник рисунка и согласованная копия](docs/RIDER_ASSET.json), [реальные MP4 и проверки](docs/RIDER_EVIDENCE.json).

GPX остаётся в памяти браузера: без отправки, сохранения пользовательских маршрутов и телеметрии. Доступны GPX 1.0/1.1 (UTF-8), треки и route points, несколько отдельных сегментов, высота и временные метки при наличии. Расстояние рассчитано по исходным координатам и не включает разрывы. Набор высоты показывается только при полной серии высот; иначе — число точек. Метки времени извлекаются, но не используются для выдуманных скоростей или длительности поездки.

Лимиты: 10 МиБ, 50 000 точек, глубина XML 64, 300 000 элементов; никакой тихой обрезки. DTD/ENTITY, исполняемое содержимое, некорректный XML и координаты отклоняются. Высоты допустимы от −12 000 до 100 000 м. Название/creator до 200 символов, описание до 2 000; длинные поля отклоняются. На кадре длинное название визуально сокращается, исходные точки сохраняются.

В v1.1 режим «Кино» начинает с обзора, приближает карту, сопровождает маркер и возвращается к полному маршруту. Камера вычисляется из времени, поэтому перемотка и экспорт воспроизводят одинаковый кадр. «Классика» сохраняет неподвижную камеру v1.0 и выбирается при системном предпочтении уменьшенного движения. Север остаётся сверху; кратчайшая дуга через 180° и независимые сегменты сохраняются. В разрывах применяется переход, а не выдуманное движение между сегментами.

Локальная карта «Кино» содержит Natural Earth 1:50m (суша, озёра, реки) и небольшой пакет 1:10m западной Норвегии (берег, острова, реальные подписи). В других регионах явно указан обзорный фон. Это не всемирная уличная карта и не навигация; детальность и высокоширотная проекция ограничены. Классический режим использует прежний 1:110m. Все необходимые слои загружаются с того же сайта до начала экспорта. [Архитектура и границы](docs/CINEMATIC_ARCHITECTURE.md), [источники и хеши](docs/GEOGRAPHY_SOURCES.json), [визуальный аудит](docs/VISUAL_UPGRADE_AUDIT.md). Числа рассчитаны по исходным GPX, независимо от камеры. На коротких/стационарных маршрутах приближение ограничено.

**Новый режим «Рельеф · 3D»** строит настоящую сетку гор и долин по лицензированному DTM10 Kartverket. «Попробовать 3D» загружает явно синтетический маршрут в локальном пакете Согне-фьорда. Камера спускается из общего вида, следует маршруту с проверкой высот/видимости и возвращается к обзору. Путь учитывает глубину сцены; разрывы GPX не соединяются. Высоты DEM и GPX разделены, вертикальный масштаб 1:1. Atlas использует дневной рельеф с высотными контурами, Night — тёмные склоны и янтарный путь. Это художественное освещение, не историческая погода.

Базовый пакет Согне ограничен регионом 30×40 км: производные сетки 50 м для Standard и 100 м для Compatibility. Исходная сетка Kartverket имеет шаг 10 м. © Kartverket, CC BY 4.0; источник обработан и округлён до метров. Вертикальный датум не указан в полученном GeoTIFF/метаданных 2020, поэтому приложение не заявляет NN2000 и не подменяет GPS-высоты. Высота камеры консервативно выше максимального рельефа пакета минимум на 350 м. Модель не знает мостов, тоннелей, дорог и подводного рельефа; края регионального пакета плавно уходят в фон. Полного мирового DEM нет.

«Авто» включает 3D только при полном покрытии и доступной подготовке сцены, иначе сообщает о выборе 2D. Явно выбранный 3D при ошибке остаётся недоступен и предлагает переключиться; GPX сохраняется в памяти для восстановления без повторного импорта. Требуется WebGL 2; поддержка H.264 проверяется отдельно. Лимиты 3D: 500 000 вершин рельефа, 400 000 вершин пути, 128 сегментов; при превышении предлагается 2D без изменения GPX. Производственный пакет остаётся меньше 5 МиБ. Потребление native/GPU-процессов может быть значительно выше размера файлов; минимальный RAM для мобильных устройств не установлен. [Архитектура/источники](docs/TERRAIN_ARCHITECTURE.md), [камера и реальные видео](docs/TERRAIN_CAMERA_VALIDATION.md), [измерения](docs/TERRAIN_PERFORMANCE.md).

По умолчанию видео длится 20 секунд: 2 секунды вступления, 16 секунд повтора, 2 секунды финала. Для 10/30/60 секунд вступление и финал также занимают по 2 секунды. Вступление показывает название и исходный маршрут, повтор подсвечивает пройденный путь по географическому расстоянию, финал показывает весь маршрут, итоговое расстояние и небольшую подпись Matawaka. В каждом кадре есть второй фактический показатель: набор высоты при полной серии высот либо число точек. Название — 1–200 единиц UTF-16, без управляющих знаков; берётся из метаданных GPX или нейтрального значения по умолчанию. Длинное название визуально сокращается только на кадре; имя файла отдельно ограничено 60 кодовыми точками. Звук отсутствует.

Предпросмотр, перемотка и экспорт используют общий детерминированный таймлайн; FPS и скорость кодирования не меняют движение. Время рядом с ползунком — время видео. Скорость и длительность реальной поездки не выводятся. Для стационарного трека показываются постоянная позиция и нулевое расстояние. Изолированные точки в разных сегментах могут переходить дискретно, без соединяющей линии.

| Качество | 16:9 | 9:16 | FPS | Целевой битрейт |
| --- | --- | --- | --- | --- |
| Совместимое (по умолчанию) | 640×360 | 360×640 | 24 | 1,5 Мбит/с |
| Стандартное | 1280×720 | 720×1280 | 24 | 5 Мбит/с |

Standard проверяется на выбранных размерах. Если кодировщик недоступен, приложение предлагает выбрать совместимое качество; автоматического снижения качества или длительности нет. Длительность: 10, 20, 30 или 60 секунд. Минутный вариант даёт 1440 кадров при тех же 24 FPS и разрешении; его предел — 48 МиБ закодированных пакетов. Для прежних вариантов сохраняются 720 кадров максимум и 32 МиБ (+ до 1 МиБ для MP4-контейнера). Это ограничение файла, не измеренный предел общей памяти браузера. Параметры фиксируются перед экспортом, конфликтующие элементы блокируются; отмена и повторный экспорт доступны. Четырёхсекундный режим сохранён только для внутренних регрессионных проверок.

## Проверки

Проверки на Windows с установленным Edge:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
npm.cmd run check
```

Или установите Chromium: `npx.cmd playwright install chromium`; без переменной PLAYWRIGHT_CHANNEL тесты используют его. Доступность H.264 зависит от ОС/кодировщика; Windows CI использует Edge. `npm.cmd run test:e2e` требует предварительного `npm.cmd run build`: тестируются dev-сервер и собранный production bundle. Playwright запускает и останавливает свои серверы автоматически.

Независимые FFmpeg и ffprobe проверяют реальный MP4: H.264, размеры, выбранную длительность, 24 FPS, точное число декодированных кадров и изменение изображения. В обычном CI сохранены короткая регрессия 4 с / 96 кадров и ограниченный экспорт Standard 20 с / 480 кадров. Локальные MP4, JSON-отчёты и снимки находятся в игнорируемом `artifacts/`. Полная приёмка 30 секунд в обоих форматах, на 5000 синтетических точках:

```powershell
$env:PLAYWRIGHT_CHANNEL = 'msedge'
$env:FULL_EXPORT_ACCEPTANCE = '1'
npm.cmd run check
Remove-Item Env:FULL_EXPORT_ACCEPTANCE
```

Для отдельной проверки (последний аргумент — длительность; без него используется регрессия 4 секунды):

```powershell
npm.cmd run validate:video -- artifacts/route-story-proof.mp4 640 360
npm.cmd run validate:video -- artifacts/story-standard-30s-landscape.mp4 1280 720 30
```

CI использует только синтетические данные. Учебный пример также синтетический. Реальный публичный Hong Kong Trail проверен отдельно и не включён в репозиторий из-за неразрешённых условий вышестоящих источников: [происхождение и результаты](docs/SAMPLE_PROVENANCE.md).

Прежняя release-приёмка воспроизводит файлы из [учебного GPX](public/samples/synthetic.gpx) и [перехода через 180°](public/samples/synthetic-antimeridian.gpx):

## Публикация

Ручной workflow GitHub Pages принимает только полный проверенный SHA main с успешной приёмкой. Build/test имеют read-only права; запись Pages/OIDC доступна только deployment job с отдельно настроенным owner approval. Защищённый Pages workflow и environment для MVP 1.7 не меняются. Пути относительные; приватные тестовые данные исключены из публичного пакета. Эта ветка не запускает deployment, не сливает PR и не изменяет стабильный tag. [Порядок выпуска](docs/RELEASE.md) и исторические журналы сохраняют результаты прежних этапов.

Production CSP остаётся ограниченным локальными ресурсами. На статическом хостинге meta CSP не заменяет все HTTP security headers; фактические заголовки и HTTPS должны проверяться после публикации. Никакие отсутствующие header-защиты не заявляются.
